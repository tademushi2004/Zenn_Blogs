> 初対面の飲み会で話題に困らないよう、心理学実験の質問集をカードのように引けるWebアプリを作りました。

## はじめに

初対面の人と何を話せばいいかわからない！！！

そこで、会話のきっかけになる質問を、 **山札からカードを引くように選べるWebアプリ「トークテーマカード」** を作りました。

まずは、完成したアプリを直接触ってみてください。

* **▶ デモを試す:** [トークテーマカード (GitHub Pages)](https://tademushi2004.github.io/talk-cards/)
* **▶ ソースコード:** [GitHubリポジトリ](https://github.com/tademushi2004/talk-cards)

## 概要と使い方（機能デモ）

**トークテーマカード** は、質問のカードを1枚ずつ引いて、隣の人に投げかけるアプリです。スマートフォンでの利用を想定していますが、PCでも使えます。サーバーもアカウントも不要で、設定と記録は、ブラウザの `localStorage` にだけ保存されます。

### 1. 山札から引く

![山札の画面のスクリーンショット](/images/talk-cards-app-01_image.png =250x)

山札を上に **スワイプ** するか、タップすると、1枚引けます。引いたカードは裏向きです。

![引いたカード（裏向き）のスクリーンショット](/images/talk-cards-app-02_image.png =250x)

裏面の色・模様・記号で、質問の段階（○ 軽め／△ 中間／◇ 深め）が、めくる前に分かります。

### 2. めくって、質問を投げかける

![めくったカード（表）のスクリーンショット](/images/talk-cards-app-03_image.png =250x)

カードを **タップ** すると、3Dで裏返って質問が表示されます。その質問を、隣の人に投げかけます。

「お互いの長所を言い合う」のように、答えるだけでなく何かをする **作業型** のカードには、やり方の説明が付きます。

### 3. 話した／パスを記録する

| 右へスワイプ（話した） | 左へスワイプ（パス） |
| --- | --- |
| ![右へスワイプ中の画面（話した）のスクリーンショット](/images/talk-cards-app-04_image.png =180x) | ![左へスワイプ中の画面（パス）のスクリーンショット](/images/talk-cards-app-08_image.png =180x) |

話し終えたら、右へスワイプして「話した」にします。気が乗らなければ、左へスワイプして「パス」にします。スワイプ中は、「✓ 話した」「✕ パス」のスタンプが浮かびます。記録は「今夜の記録」で一覧でき、間違えたときは「戻す」で取り消せます。

| 操作 | スマホ | PC |
| --- | --- | --- |
| 引く | 山札を上にスワイプ、またはタップ | ↑ / スペース |
| めくる | カードをタップ | ↑ / スペース |
| 話した | 右へスワイプ | → |
| パス | 左へスワイプ、または「✕ パス」ボタン | ← |
| 戻す | 左下の「戻す」ボタン | Z |

### 4. 場に合わせたフィルター

「設定」から、出題する質問を絞り込めます。

| 設定 | 内容 |
| --- | --- |
| 重めの質問を除く | 死・家族・つらい記憶などに触れる9枚を除く。初期状態はON（35枚が出題される） |
| 段階 | 軽め・中間・深めから選ぶ |
| 出典 | 36の質問、ディープトーク定番から選ぶ |

収録している質問は、全44枚です。選んだ理由は、次の章で説明します。

| 出典 | 枚数 | 内容 |
| --- | --- | --- |
| 36の質問 | 36 | 原論文の付録の質問を、英語原文から独自に日本語訳したもの。段階は原典の Set I・II・III に対応する |
| ディープトーク定番 | 8 | 書籍で、ディープトークの典型例として紹介されている質問を、言い換えて収録したもの |

## 質問は、研究に根拠のあるものから選んだ

このアプリに入れる質問は、何でもよいわけではありません。盛り上がらない質問や、踏み込みすぎる質問では、かえって気まずくなります。そこで、 **心理学の研究に根拠のあるもの** から選びました。

### 36の質問

「36の質問」は、 **見知らぬ2人を親しくさせること** を狙って作られた質問集です。心理学者アーロンらの実験[^1]では、初対面の2人組が、この質問に交互に答え合う形で使われています。

質問は3つのSet（各12問）に分かれ、後ろのSetほど踏み込んだ内容になります。

| Set | 段階 | 質問の例（筆者訳） |
| --- | --- | --- |
| I | 軽め | あなたにとって「完璧な1日」とは、どんな1日ですか？（Q4） |
| II | 中間 | いちばん大切にしている思い出は何ですか？（Q17） |
| III | 深め | 最後に人前で泣いたのはいつですか？ ひとりで泣いたのは？（Q30） |

最初は気軽な質問から始まり、だんだん、普段は初対面の人に話さないようなことへ進んでいきます。

### ディープトーク

もうひとつは、 **ディープトーク** です。社会心理学の用語で、雑談では交わさないような、深みのあるテーマを扱った会話を指します。雑談よりも、相手との距離を縮める働きがあるとされています[^2]。36の質問とは、別の概念です。

書籍[^3]で、ディープトークの典型例となる質問が紹介されていたので、アプリに加えました。たとえば、次のような質問です。

| 質問の例（筆者による言い換え） |
| --- |
| あなたのロールモデルは誰ですか？ |
| 人生で最も誇りに思うことは何ですか？ |

紹介されていた質問のうち、内容が近い2問は、36の質問に統合しました。残りの8問が、アプリの「ディープトーク定番」です。

ただし、筆者が研究論文で直接確認した質問ではありません。そのため、アプリと記事では、「書籍で紹介されているディープトークの典型例」と書き、「効果が確認された質問」とは書いていません。

### 質問データの作り方

36の質問は、先ほどの論文の付録に載っています。最初は、36の質問を紹介していた別の書籍の、日本語版の言い換えをそのまま使っていましたが、孫引きを避けるために、 **原論文の英語原文から訳し直しました。**

訳し直すと、意味がずれている箇所が見つかりました。たとえば、Q33は「今夜、誰とも連絡が取れないまま死ぬとしたら、伝えておかなかったことで、いちばん後悔するのは何か」に加えて、「なぜ、まだ伝えていないのか」まで尋ねています。参照していた日本語の紹介では、この後半の問いが抜けていました。Q19、Q23、Q26、Q31も、原文に合わせて直しました。

質問のデータは、次の項目を持つ配列です。

| 項目 | 意味 |
| --- | --- |
| `level` | 段階。1=軽め、2=中間、3=深め（36の質問は原典のSetと同じ） |
| `set` | 原典のSet番号。ほかの質問は `null` |
| `heavy` | `true` なら「重めを除く」スイッチの対象 |
| `kind` | `"question"`（普通の質問）か、 `"task"`（作業型） |
| `hint` | 作業型の説明文 |
| `source` | 出典（`"aron1997"` か、 `"suzuki"`） |
| `deeptalk` | `true` なら「ディープトーク定番」バッジを表示 |

```javascript
{ id: "q11", text: "これまでの人生を、できるだけ詳しく相手に話してみましょう。",
  level: 1, set: 1, heavy: false, kind: "task",
  hint: "原典では4分間。飲み会では1分くらいでざっくりと。",
  source: "aron1997", deeptalk: false }
```

作業型の説明は、飲み会向けに補足しています。この例では、原典の4分間を1分くらいにしました。原典そのままではないことは、アプリの中にも書いています。

データを JSON ではなく `questions.js` に置いているのは、 `index.html` をローカルで直接開く（`file://`）と、 `fetch` が失敗するためです。JavaScriptファイルなら、ローカルでも、GitHub Pagesでも、同じように動きます。

## 作った流れ

開発は、次の順で進めました。

1. **企画と質問の選び方を決める。** 36の質問をカードにして引けるようにすること、追加の質問を足すこと、重い質問を除くスイッチを付けることを決めました。
2. **設計案を確認してから、ステップごとに実装する。** 外部ライブラリを使わない構成（`index.html` / `style.css` / `questions.js` / `gesture.js` / `app.js`）の案を確認してから、Claude Codeと対話しながら、1ステップずつ実装しました。
3. **「カードを引く手触り」を足して、v2に作り直す。** v1は動きましたが、カードが小さく、引くワクワク感がありませんでした。主にスマホで使うので、本物のカードを引く手触りを足す案を出してもらい、採否を決めました。
4. **GitHub Pagesで公開し、iPhoneで確認する。** 実機で触ると、 **ダブルタップで画面が拡大され、次のカードをめくる操作が難しくなる** 問題が見つかりました。使い心地への影響が大きかったので、拡大を止める処理を入れて直しました（下の折りたたみで説明します）。修正後は、筆者のiPhoneで、ダブルタップしても画面が拡大されないことを確認しました。

:::details ダブルタップ拡大を止めた修正（viewport・CSS・JavaScript）

画面の拡大を止める処理は、次の3か所に入れています。

| 場所 | 内容 |
| --- | --- |
| `viewport` | `maximum-scale=1, user-scalable=no` を指定する |
| CSS | `touch-action: manipulation` を、タップする要素に指定する |
| JavaScript | iPhoneのSafariが拡大に使うイベントを止める |

```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no, viewport-fit=cover">
```

`touch-action` は継承されないので、タップする要素に個別に指定します。スワイプで操作するカード部分（`.stage`）は、 `touch-action: none` のままです。

```css
html, body, button, label, summary, dialog, .sheet {
  touch-action: manipulation;
}
```

iOS 10以降のSafariは、 `user-scalable=no` を無視してピンチ拡大を許します。また、カード部分の `touch-action: none` だけでは、ダブルタップ拡大が止まらないことがありました。そこで、JavaScriptでも止めています。

```javascript
// ピンチ拡大を止める
["gesturestart", "gesturechange", "gestureend"].forEach(function (type) {
  document.addEventListener(type, function (e) { e.preventDefault(); });
});
document.addEventListener("touchmove", function (e) {
  if (e.touches && e.touches.length > 1) e.preventDefault();
}, { passive: false });

// カード部分のダブルタップ拡大を止める
els.stage.addEventListener("touchend", function (e) {
  if (e.cancelable) e.preventDefault();
}, { passive: false });
```

カード部分の操作は、 `pointer` イベントで処理しています。 `pointer` イベントは `touchend` より先に届くので、 `touchend` を止めても、タップやスワイプの判定には影響しません。

なお、拡大を禁止すると、画面を拡大して読みたい人には不便になります。このアプリは、カードを画面幅の約88%まで大きくして、文字を読みやすくすることで補っています。
:::

### 実装中のつまずき

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| `app.js` から質問データを参照できない | 通常の `<script>` で `const` を使うと、 `window` のプロパティにならない | `questions.js` の宣言を `var` に変更した |
| テストで、ゆっくり50px動かしただけなのにカードが捨てられた | テストの合成イベントが同じ時刻に発生し、速さが極端に大きく計算された | テストで `performance.now` を疑似時計に差し替えた |
| 2周目に入るとエラーが出た | シャッフルを知らせる関数 `toast` を定義し忘れていた | 画面のテストに「1周回す」ケースを足して発見し、修正した |
| スワイプ中のスタンプが、段階のバッジに重なった | 表示位置の指定が上すぎた | スクリーンショットで見つけて、表示位置を下げた |

## 工夫したポイント

HTML / CSS / Vanilla JavaScript だけで作っており、外部ライブラリは使っていません。ここでは、山札の仕組み、スワイプの判定、色だけに頼らない段階表示を紹介します。

### 1. 1周するまで重複しない山札

山札は、 **シャッフルバッグ方式** です。全カードをシャッフルして配列に入れ、末尾から1枚ずつ引くので、1周するまで同じカードは出ません。

```javascript
// Fisher-Yates シャッフル（元の配列は変更しない）
function shuffle(arr, rnd) {
  var a = arr.slice();
  for (var i = a.length - 1; i > 0; i--) {
    var j = Math.floor(rnd() * (i + 1));
    var t = a[i];
    a[i] = a[j];
    a[j] = t;
  }
  return a;
}
```

全部引いたら、シャッフルし直します。このとき、周の境目で同じカードが続かないように、直前のカードと先頭が同じなら入れ替えます。

```javascript
function refill() {
  bag = shuffle(pool, rnd);
  // 作り直した直後に、直前と同じカードが続けて出ないようにする
  if (bag.length > 1 && current && bag[bag.length - 1].id === current.id) {
    var t = bag[bag.length - 1];
    bag[bag.length - 1] = bag[0];
    bag[0] = t;
  }
}

function peek() {
  if (pool.length === 0) return null;
  if (bag.length === 0) refill();
  return bag[bag.length - 1];
}
```

`peek()` は、次のカードを引かずに見る関数です。裏面に次のカードの段階を出すために使っています。

山札の厚みは、残り枚数に比例して、最大6枚の重なりで描きます。

```javascript
function deckLayers(remaining, total, maxLayers) {
  if (remaining <= 0 || total <= 0) return 0;
  return Math.max(1, Math.min(maxLayers, Math.ceil(remaining / total * maxLayers)));
}
```

1周するとシャッフルのアニメーションが動き、「2周目」と通知されます。

### 2. スワイプ判定を、テストできる関数にする

カードを引く・捨てる操作は、指の動きから判定します。判定の部分を **画面に依存しない純粋な関数** `decideSwipe` に切り出したので、Node.jsだけでテストできます。

| 条件 | 結果 |
| --- | --- |
| 80px以上動かした | 速さに関係なく確定 |
| 28px以上動かし、0.45px/ms以上の速さで、動かした向きと勢いの向きが同じ | 確定（フリック） |
| それ以外 | 元の位置に戻す |

指を離したときの速さは、 **直近100msの移動** から求めます。

```javascript
// g: { dx, dy, vx, vy } / axis: "x"（左右）または "up"（上）
function decideSwipe(g, axis, opt) {
  var o = DEFAULTS; // opt による設定の上書きは省略（DEFAULTS は下の定数）
  if (axis === "x") {
    var ax = Math.abs(g.dx);
    var sameDir = (g.dx > 0 && g.vx > 0) || (g.dx < 0 && g.vx < 0);
    if (ax >= o.distance || (sameDir && Math.abs(g.vx) >= o.velocity && ax >= o.minDistance)) {
      return g.dx > 0 ? "right" : "left";
    }
    return null;
  }
  if (axis === "up") {
    if (-g.dy >= o.distance || (g.vy <= -o.velocity && -g.dy >= o.minDistance)) return "up";
    return null;
  }
  return null;
}
```

カードの位置は、状態ごとにCSS変数 `--y` で決めています。ドラッグ中だけ、JavaScriptが `transform` を直接書きます。指を離したら、その `transform` を消します。すると、CSSの `transition` で、元の位置に戻ります。

テストは、次のコマンドで実行できます。

```sh
node tests/logic.test.js
```

| テストの対象 | 確認していること |
| --- | --- |
| データ | 件数と、36問がSetごとに12問であること |
| フィルター | 条件ごとの件数（44 / 35 / 12 / 8 / 0枚） |
| 山札 | 40周しても1周内で重複しないこと、周の境目で同じカードが続かないこと、戻す操作 |
| 設定・記録 | 壊れた保存データの扱い |
| スワイプ判定 | ゆっくりした操作と、素早いフリック |

画面の自動操作（上スワイプで引く、タップでめくる、左右スワイプなど）は、jsdomで確認しました。こちらは、リポジトリには含めていません。

### 3. 色だけに頼らない段階表示

質問の段階は、裏面の **色・模様・記号・文字** の4つで区別します。色の見え方が違う人でも、色以外の手がかりで読み取れます。

| | 軽め | 中間 | 深め |
| --- | --- | --- | --- |
| 裏面 | ![軽めの裏面](/images/talk-cards-app-05_image.png =110x) | ![中間の裏面](/images/talk-cards-app-01_image.png =110x) | ![深めの裏面](/images/talk-cards-app-07_image.png =110x) |
| 色 | 緑 `#2f7a62` | 琥珀 `#b06d12` | 紫 `#5b3f8c` |
| 模様 | ドット | 斜線 | ひし形 |
| 記号 | ○ | △ | ◇ |
| 文字 | 軽め | 中間 | 深め |

裏向きの時点で、次のカードの段階が分かります。「深めが来た…」という緊張感も出ます。

そのほかに、次の点に配慮しました。

* **裏向きの間は、質問文を読み上げさせない。** 読み上げソフトが、めくる前の質問を読まないように、 `aria-hidden` を指定しています。
* **ダークモードに対応する。** 色は、ライトとダークで別々に決めています。
* **「動きを減らす」設定に対応する。** この設定の端末では、アニメーションを最小にします。

## おわりに

外部ライブラリを使わなくても、スマホで「引く、めくる、スワイプする」手触りは作れました。この開発で学んだことは、次の3つです。

* 出典は、本ではなく原典に当たる。訳し直すと、ずれが見つかる。
* 判定ロジックは、純粋な関数にして、テストする。
* 色だけに頼らず、模様・記号・文字でも伝える。

実機（iPhone）での確認では、ダブルタップで画面が拡大される問題が見つかりました。実機で触らないと気づけない問題があるので、公開したあとの確認も大切です。
