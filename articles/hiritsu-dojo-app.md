> 線の上の比率（A:B = 1:2 など）を目分量で当てる練習ゲーム「比率道場」を、Claude Codeと対話しながら作りました。

## はじめに

絵を描いていて、**「ここを1:2に分けたい」と思っても、位置が目分量でずれてしまう**ことはありませんか？

人体のバランスや構図の分割など、絵では比率を扱う場面が多くあります。定規で測れば正確に分けられますが、描きながら毎回測るわけにはいきません。目分量の精度は、練習で上げられるはずです。

そこで、**線の上で指定された比率の位置を当てる**クイズ形式の練習ゲーム **「比率道場」** を作りました。開発は、要件定義から公開まで、Claude Codeと対話しながら進めています。

まずは、完成したアプリを直接触ってみてください。

* **▶ デモを試す:** [比率道場 (GitHub Pages)](https://tademushi2004.github.io/hiritsu-dojo/)
* **▶ ソースコード:** [GitHubリポジトリ](https://github.com/tademushi2004/hiritsu-dojo)

## 概要と使い方（機能デモ）

**比率道場** は、1ラウンド10問のクイズです。パソコンでもスマホでも遊べます。

### 1. 出題と回答

![出題画面のスクリーンショット](/images/hiritsu-dojo-question.png =250x)

「A:B = 1:3 の位置にカーソルを置いてください」のように、比率が出題されます。線の上をなぞってカーソルを動かし、**「決定」** を押して回答します。出題中は、目盛りや補助線などのヒントは表示されません。

線は、水平の直線、斜めの直線、曲線の3種類です。問題ごとに新しく作られます。出題される比率は、1:1、1:2、1:3、2:3、3:5 と、その向きを入れ替えたものの全9種類です。

### 2. 判定

![判定画面のスクリーンショット](/images/hiritsu-dojo-result.png =250x)

回答すると、評価、誤差、自分の位置、正解の位置が表示されます。正解の位置は、線上の青い輪で示されます。

誤差は、**正解位置と回答位置の差（線に沿った長さ）を、線の全長で割った値（%）** です。評価と得点は次のとおりです。

| 評価 | 誤差 | 得点 |
| --- | --- | --- |
| Perfect | 2%以内 | 100点 |
| Great | 2%を超え5%以内 | 70点 |
| Good | 5%を超え10%以内 | 40点 |
| Miss | 10%を超える | 0点 |

### 3. 最終結果

![最終結果のスクリーンショット](/images/hiritsu-dojo-final.png =250x)

10問が終わると、評価ごとの回数、今回の得点（満点は1000点）、自己ベストが表示されます。自己ベストは、ブラウザの `localStorage` に保存され、アプリから外部へ送信されることはありません。

## Claude Codeで作った流れ

開発は、次の順で進めました。

1. **要件定義を文書にする。** アプリの目的、遊び方、評価の基準、得点を、Claude Codeと対話しながらまとめ、文書として保存しました。
2. **計画を出させて、確認してから実装する。** 実装の前に、Claude Codeの plan mode で計画を出させました。計画の内容を確認し、納得してから実装に進みました。
3. **GitHub Pages で公開し、実機で確認する。** PCとスマホの両方で動かしました。
4. **見つけた問題を修正する。** スマホで遊ぶと、「決定」ボタンは画面に収まっていましたが、回答後の「次へ」ボタンが画面の下に見切れてしまう問題が見つかりました。そこで、ボタンを画面下部の1つに固定する構成に改めました。あわせて、評価の配色も、色覚の違いに配慮して見直しました。改善の内容は、後述の「使用した技術」の「Duolingoを参考にしたUI/UX」と「ユニバーサルカラーデザインを意識した色の設計」で説明しています。

## 工夫したポイント

HTML / CSS / Vanilla JavaScript だけで作っており、外部ライブラリは使っていません。ここでは、判定の仕組み、Duolingoを参考にしたUI/UX、ユニバーサルカラーデザインを意識した色の設計を紹介します。

### 1. 「線に沿った長さ」で判定する

曲線の上では、2点の直線距離で誤差を測ると、実際の比率とずれてしまいます。そこで、**どの線も細かい折れ線として扱い、各点までの累積長を持たせる**ことにしました。直線は、点が2つだけの折れ線です。曲線は、3次ベジェ曲線を200本の線分に分けて近似します。こうすると、直線も曲線も、同じ判定のコードで扱えます。

```javascript
// 点の並びから、累積長と全長を計算して線のデータを作る
function buildLine(points) {
  const lengths = [0];
  for (let i = 1; i < points.length; i++) {
    const seg = Math.hypot(
      points[i].x - points[i - 1].x,
      points[i].y - points[i - 1].y
    );
    lengths.push(lengths[i - 1] + seg);
  }
  return { points, lengths, totalLength: lengths[lengths.length - 1] };
}
```

判定では、正解の位置（Aからの距離）と、カーソルの位置（Aからの距離）の差を、全長で割ります。

```javascript
const correctDistance = line.totalLength * a / (a + b);
// 誤差 = 正解位置とのずれ（線に沿った長さ）÷ 線の全長 × 100
const errorPercent =
  Math.abs(correctDistance - cursorDistance) / line.totalLength * 100;
```

ポインターの座標から、線上でいちばん近い点の「Aからの距離」を求める処理は、折れ線の各区間に座標を射影して探しています。

:::details 線上でいちばん近い点を求めるコード（JavaScript）
```javascript
// 座標 (x, y) にいちばん近い線上の点の「Aからの距離」を返す
function closestDistance(x, y) {
  const { points, lengths } = line;
  let bestDistance = 0;
  let bestGap = Infinity; // 線までの距離の2乗（いちばん近いものを探す）
  for (let i = 1; i < points.length; i++) {
    const p = points[i - 1];
    const q = points[i];
    const dx = q.x - p.x;
    const dy = q.y - p.y;
    const segLength2 = dx * dx + dy * dy;
    // この区間に射影する。0〜1 の範囲に収めるので、区間の外には出ない
    let t = segLength2 === 0 ? 0 : ((x - p.x) * dx + (y - p.y) * dy) / segLength2;
    t = Math.min(Math.max(t, 0), 1);
    const gapX = x - (p.x + dx * t);
    const gapY = y - (p.y + dy * t);
    const gap = gapX * gapX + gapY * gapY;
    if (gap < bestGap) {
      bestGap = gap;
      bestDistance = lengths[i - 1] + (lengths[i] - lengths[i - 1]) * t;
    }
  }
  return bestDistance;
}
```
:::

### 2. Duolingoを参考にしたUI/UX

語学学習アプリ Duolingoの優れたUI/UX を参考にしました。進み具合を画面上部に示し、操作を画面下部のボタンに集める構成に改めています。

* **ボタンは1つだけ、位置は固定。** 回答するときも、次へ進むときも、画面下部の同じ位置のボタンを押します。ラベルは局面に合わせて、「決定」→「次へ」→（最終問題のあと）「結果を見る」→「もう一度遊ぶ」と切り替わります。
* **画面上部に、進捗バーを置く。** 10問を10個の区切りで表し、いま解いている問題まで塗ります。「第 N 問 / 10」と、累計の得点も、あわせて表示しています。画面の上部に状況、下部に操作と、役割を分けています。
* **回答後は、ボタンの色が変わる。** 藍色から濃い緑に変わり、次へ進む操作だと分かります。
* **結果の表示場所は、最初から確保しておく。** 回答後は、評価、誤差、あなたの位置、正解の位置が、ボタンの上の欄に表示されます。場所を先に確保しているため、表示が増えても、ボタンの位置は動きません。
* **ページ全体はスクロールさせない。** 高さには、スマホのアドレスバーの出し入れに影響されない `100dvh` を使っています。操作バーには、iPhone のホームバーと重ならないように、`env(safe-area-inset-bottom)` で余白を足しています。
* **ダブルタップで拡大されない。** ボタンには `touch-action: manipulation` を指定しています。

```css
/* 画面全体を縦に並べる: 上部 / 中央（伸縮） / 下部（固定の操作バー） */
#app {
  display: flex;
  flex-direction: column;
  height: 100%;   /* dvh に対応していない古いブラウザ用 */
  height: 100dvh;
}

/* ===== 下部: 固定の操作バー ===== */
#bar {
  flex: none;
  background: var(--card);
  border-top: 1px solid var(--line);
  padding: 10px 16px;
  /* iPhone のホームバーと重ならないようにする */
  padding-bottom: calc(10px + env(safe-area-inset-bottom));
  /* 左右の余白の指定は省略 */
}
```

### 3. ユニバーサルカラーデザインを意識した色の設計

評価の4段階は、**背景の色、文字の色、アイコン**を組み合わせて、色の見え方が違う人でも読み取れるようにしました。

| 評価 | 背景 | 文字 | アイコン | 文字のコントラスト比 |
| --- | --- | --- | --- | --- |
| Perfect | 濃い青 `#004B7A` | 白 | ◎ | 9.2:1 |
| Great | 水色 `#7CC4EE` | 濃い墨色 `#1F1D1A` | ○ | 8.8:1 |
| Good | オレンジ `#D98C00` | 濃い墨色 `#1F1D1A` | △ | 6.2:1 |
| Miss | 朱赤 `#C25400` | 白 | ✕ | 4.6:1 |

* **背景の明るさに合わせて、文字の色を変える。** 暗い背景には白、明るい背景には濃い色の文字を使っています。どの組み合わせも、コントラスト比が WCAG の基準（4.5:1 以上）を満たしています。比率は、計算して確認しました。
* **色の明るさにも差をつける。** 4色は、色相だけでなく明るさも違うため、色の違いが分かりにくい場合でも区別しやすくなります。
* **色だけに頼らない。** 評価は、色に加えて、文字（Perfect など）とアイコン（◎ ○ △ ✕）で区別できます。盤面の「あなた」と「正解」も、色だけでなく、塗りつぶしの丸（あなた）と輪（正解）という形で区別しています。
* **補助的な文字も、基準を満たす。** 灰色の補助的な文字も、背景に対して 4.5:1 以上にしています。
